  ### The Problem: A Punitive Reward Function

  The issue lies in these lines of code that calculate the reward:


  `python
          # ENHANCED REWARD: Penalize downside risk (Sortino-like)
          if step_pnl < 0:
              reward = step_pnl * (1 + self.downside_risk_aversion)
          else:
              reward = step_pnl
  `


  Your downside_risk_aversion parameter is set to 0.5. This means:
  *   If the agent makes a profit (step_pnl > 0), its reward is step_pnl.
     If the agent makes a loss (`step_pnl` < 0), its reward is `step_pnl  1.5`. The loss is magnified by 50%.


  Faced with this asymmetric penalty, the agent made a "logical" choice to minimize its punishment. It learned that by hedging 100% of the time:
  1.  It eliminates all market risk, avoiding the possibility of large, magnified losses.
  2.  It accepts a small, guaranteed loss on every step due to transaction costs.


  The agent chose a slow, predictable loss over a risky strategy where losses were punished far more heavily than gains were rewarded. It 
  literally learned that the best way to succeed was to never try to win.

  ### The Solution: Balance the Reward

  The reward function must be balanced. The agent should be trying to maximize profit, not just avoid punishment. The simplest and most effective 
  way to fix this is to remove the penalty and make the reward directly proportional to the profit or loss on each step.


  I will modify the reward calculation to be simply:

  reward = step_pnl

  This change will treat gains and losses symmetrically, encouraging the agent to learn a genuine profit-seeking strategy instead of simply 
  hiding from risk.
